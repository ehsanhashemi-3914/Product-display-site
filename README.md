# مهر نماز احسان — فروشگاه نمایشی محصولات

سایت نمایش محصولات **مهر نماز احسان** (تولیدی سید جواد هاشمی) به همراه پنل مدیریت.
تمام صفحات فارسی و راست‌به‌چپ هستند.

محصولات و تصاویر در یک **دیتابیس پستگرس** ذخیره می‌شوند. یعنی هر کسی با هر دستگاهی
لینک سایت را باز کند، همان محصولاتی را می‌بیند که شما وارد کرده‌اید.

**برای انتشار سایت روی اینترنت: [DEPLOY.md](DEPLOY.md) را بخوانید.**

## اجرای محلی

یک‌بار:

```bash
npm install
```

بعد در **دو ترمینال جدا**:

```bash
npm run db:local
```

```bash
npm run dev
```

سپس <http://localhost:3200> برای فروشگاه و <http://localhost:3200/admin> برای پنل مدیریت.
رمز پیش‌فرض محیط محلی در فایل `.env.local` است.

| دستور | کار |
| --- | --- |
| `npm run dev` | اجرای سایت روی پورت ۳۲۰۰ |
| `npm run db:local` | پستگرس محلی (بدون نیاز به نصب چیزی) |
| `npm run build` | ساخت نسخهٔ تولید |
| `npm run lint` | بررسی ESLint |

> پورت عمداً ۳۲۰۰ است تا با پروژه‌های دیگرتان روی ۳۰۰۰ قاطی نشود.

## تنظیمات

همهٔ تنظیمات از متغیرهای محیطی خوانده می‌شوند — نمونه در [.env.example](.env.example):

| متغیر | کار |
| --- | --- |
| `DATABASE_URL` | آدرس اتصال پستگرس (روی ورسل خودکار تنظیم می‌شود) |
| `ADMIN_PASSWORD` | رمز ورود به پنل مدیریت |
| `AUTH_SECRET` | کلید امضای کوکی ورود |
| `DATABASE_POOL_MAX` | اختیاری؛ برای دیتابیس محلی روی `1` |

شمارهٔ تماس، آیدی‌ها و نام برند در [lib/config/site.ts](lib/config/site.ts) است.

## امنیت پنل

- بررسی رمز **روی سرور** انجام می‌شود، نه در مرورگر.
- کوکی ورود `httpOnly` است؛ جاوااسکریپت اصلاً نمی‌تواند بخواندش.
- همهٔ مسیرهای تغییر داده (افزودن، ویرایش، حذف، آپلود) کوکی را دوباره بررسی می‌کنند،
  پس دست‌کاری کد سمت مرورگر هیچ راهی باز نمی‌کند.
- عوض کردن `ADMIN_PASSWORD` به‌صورت خودکار همهٔ ورودهای قبلی را باطل می‌کند.
- در صفحهٔ فروشگاه هیچ لینکی به `/admin` وجود ندارد.

## Stack

Next.js 16 (App Router) · React 19 · TypeScript (strict) · Tailwind CSS v4 ·
lucide-react · Postgres (`pg`).

## Structure

```
app/
  page.tsx                     صفحهٔ فروشگاه — از دیتابیس رندر می‌شود
  admin/                       داشبورد، فهرست، افزودن/ویرایش، تنظیمات
  api/
    products/                  خواندن عمومی؛ تغییرات فقط با ورود
    auth/                      ورود، خروج، بررسی نشست
    upload/  images/[id]/      آپلود و نمایش تصاویر
    settings/logo/             لوگوی فروشگاه
components/
  products/                    اجزای صفحهٔ عمومی
  admin/                       اجزای پنل مدیریت
  ui/                          اجزای پایه (دکمه، ورودی، دیالوگ، توست، …)
lib/
  db/                          اتصال پستگرس و پرس‌وجوها (فقط سمت سرور)
  products/                    مدل داده، مخزن، سرویس، اعتبارسنجی، استور
  auth/                        نشست مدیر
  storage/                     پردازش و آپلود تصویر (سمت مرورگر)
types/
```

## نکته‌های معماری

### یک نقطه برای تعویض محل ذخیرهٔ داده

`lib/products/repository.ts` رابط `ProductRepository` را تعریف می‌کند و
`lib/products/index.ts` تنها جایی است که پیاده‌سازی انتخاب می‌شود.

همین ساختار باعث شد جابه‌جایی از حافظهٔ مرورگر به دیتابیس، **بدون تغییر حتی یک
کامپوننت** انجام شود. پیادهٔ قبلی هنوز در `local-repository.ts` هست و برگشتن به آن
یک خط است.

### تصاویر

تصاویر در همان دیتابیس ذخیره می‌شوند و از مسیر `/api/images/<id>` سرو می‌شوند.
این تصمیم عمدی است: یک سرویس ذخیره‌سازی جداگانه یعنی یک اکانت دیگر، کلیدهای دیگر و
یک چیز دیگر که می‌تواند اشتباه تنظیم شود. برای یک کاتالوگ چند ده عکسی، این روش کافی
است و کل راه‌اندازی سایت را به «فقط یک دیتابیس» کاهش می‌دهد.

عکس‌ها قبل از آپلود در مرورگر کوچک می‌شوند (حداکثر ۱۴۰۰ پیکسل) و با هدر کش دائمی سرو
می‌شوند.

### پشتیبان‌گیری

با اینکه داده روی سرور است، امکان **دریافت فایل پشتیبان** و **بازیابی** در
«تنظیمات و پشتیبان» باقی مانده — برای انتقال بین محیط‌ها و آسودگی خاطر.

### لوگو

از پنل مدیریت: **تنظیمات و پشتیبان → انتخاب فایل لوگو**. حاشیهٔ خالی دور طرح خودکار
بریده و تصویر مربع می‌شود. لوگو هم در دیتابیس ذخیره می‌شود، پس برای همهٔ بازدیدکنندگان
دیده می‌شود.
